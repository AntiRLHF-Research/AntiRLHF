# 提交和合并的实际范围

## 从真实工作树出发

阅读当前分支和本次变更，按路径或改动块暂存。查看已暂存内容，排除凭据、构建垃圾、临时脚手架、探索性测试、其他任务和用户未要求提交的修改。提交粒度围绕连贯能力与结构变化，禁止为了每个红绿步骤切碎历史。

PR 的比较基准使用实际目标分支或任务起点。一个任务有多个提交时，`HEAD~1` 会只覆盖最后一次变化；根据实际分叉与目标选择范围。

## 合并冲突

按当前正式契约处理双方变更。冲突同时改变数据模型时，统一定义后迁移受影响调用方，禁止为了让两边都保留而建立新的版本桥。真实并存需求在产品边界明确处理。

合并后的真实组合与之前单分支不同，运行受影响入口或既有集成检查。只为确认该组合产生的新风险选择检查。

## PR 正文

写本次用户能力、决定性的结构变更和维护者需要注意的操作。引用实际问题和已有命令结果即可。禁止为短修改生成风险矩阵、证据链、分阶段收尾报告或夸张的安全声明。

工具创建 PR 失败时明确说明实际阻塞，保留分支或补丁。没有成功返回链接的 PR 不作已创建报告。
