# 按使用方式组织交付

## 教学场景

同一个项目可能交付给最终用户运行，也可能交给维护者继续检查差异。先明确接收者接下来要执行的操作，再决定归档内容。不要把开发工作区原样当安装包，也不要在审阅交付中删除用户要求保留的 Git 状态。

## 可安装分发物

安装包包含运行代码、必要资源、正确入口和实际采用依赖的声明。构建从项目当前正式来源产生，生成文件按既有工具生成。临时探针、探索数据、未采用代码和无用途测试脚手架留在开发侧。

安装位置、用户数据目录和配置更新分别有所有者。更新程序保留真实用户数据与凭据；需要迁移时执行已选迁移策略。只为内部模型整理而设计多版本永久读取器会扩大长期负担，应让持久化边界承担一次必要迁移。

依赖许可按真实分发内容保留必需声明，集中维护来源和许可证。不要把同一许可复制进每个短参考正文，或让普通使用者反复核验来源。

## 供维护者审阅的仓库

用户要求保留提交、暂存修正与未暂存扩展时，交付包含 `.git` 的完整仓库。保留现有分支和提交，不为看起来整洁压平历史。工作区中的新文件也必须进入归档，保持其未跟踪、未暂存状态。

用 [index 与工作区方法](../../git-workspaces/references/index-and-working-tree.md)理解实际差异。提交给谁、是否推送、是否合并由当前授权决定；创建本地归档不附带远程发布。

## 入口必须实际可用

CLI 包的安装命令应能找到程序和资源；Web 分发物包含真实构建产物及启动说明；技能包的本地引用应能从分发位置解析。通过一种真实安装或解压后的使用路径确认接线，观察已改变的部分。

如果安装器遇到同名用户文件，采用已定覆盖或停止策略，避免静默破坏。禁止为一个目录复制操作创造庞大的迁移框架；现有成熟安装工具适用时直接使用。

## 最终说明面向接收者

说明交付物、入口、实际改变和真实阻塞。审阅仓库说明如何查看三层差异；运行包说明如何安装与使用。用户不需要一份“经过多轮严格验证”的过程宣传，也不需要重复的许可证审计叙述。

交付文件已经包含所需内容并能按约定使用后结束。发现实际遗漏就修复对应来源；禁止自动继续灰度、远程推送、合并和发布。
