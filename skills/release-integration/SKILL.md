# 集成与发布

## 确认要交付的实际对象

读取用户要求的目标分支、包、环境和动作。提交、PR、合并、公开发布分别处理。使用当前工作树、实际差异和项目现有发布配置确定内容，保留用户无关修改。

日常开发任务完成功能即可。用户提出集成或发布时才开展这里的工作；禁止把每次修改自动扩成版本发布、验收矩阵和证据归档。

## 使用既有交付机制

沿项目实际构建、打包、发布和安装命令完成交付。编译产物和包内容要包含本次能力需要的注册、资源与依赖。成熟工具已有的打包和版本能力直接使用；不要再写一层通用发布框架。

接口和文档同步描述当前结果。更新发布说明时写用户能使用的变化、实际迁移和真实已知问题，省去自己执行了多少步骤的展示。方法见 [提交与集成](references/commits-and-integration.md)。

## 在真实边界确认结果

同一工作树已经运行的相关检查继续有效。合并改变了组合、打包引入新路径或目标环境不同，就检查该变化可能影响的行为。包实际安装、注册入口和启动路径比重复字段断言更有价值。

真实发行涉及版权声明、持久数据或公开兼容时处理其具体责任。供应链摘要或实验冻结由对应真实要求触发，避免对普通提交重复做文件摘要表。

## 执行授权动作并结束

发布、推送共享分支和重写历史按用户授权执行；仅获得本地实现授权时保留本地成果。工具明确返回失败就报告状态和影响，保留可恢复产物。针对失败的回滚与重试见 [发布边界](references/package-and-release.md)。

交付链接、版本或实际产物位置及必要操作说明。已完成目标后停止，不自动追加新的独立审查、稳定化阶段和收尾程序。

交付源码、安装包或可审阅仓库时，读取[按使用方式组织交付](references/deliverable-shapes.md)，让内容、安装和权限匹配真实接收者。
