# 找全实际消费者，完成一次替换

## 追踪从定义开始

读取被替换定义、导出路径和相邻调用。使用语言服务的引用查找，辅以源码搜索查字符串注册、配置键、环境变量和生成模板。接口可能从 CLI、路由、任务处理器、插件注册表或依赖注入入口被调用，按真实发现关系展开。

关键词命中只帮助定位。历史发布记录中的旧名留在历史中；现行示例调用旧接口则同步修改。生成文件从其权威来源修改后重建，避免同时手工维护两份代码。

## 教学情境：替换状态存储 API

原 `saveLegacyState` 被页面保存、CLI 导入和定时同步调用。新存储拥有完整验证和原子写入。

先定义新操作的参数与返回结果，迁移页面保存路径，再迁移 CLI 和同步。同步调用若通过注册表发现，更新注册目标和配置中的处理器名。把当前指南和示例切到新调用。最后查旧导出和真实引用，删除旧存储、字段转换及专用 Mock。

某个调用方仍需要数据，新契约应表达它的真实需求。直接修正新契约及已经迁移的消费者，禁止因前两处已改完就冻结一个错误接口。

## 分批施工与双轨的区别

一次重构中临时存在新旧代码是施工状态。持续推进剩余消费者，完成后删除旧路径。真实分批发布且已有客户端需要兼容时，在对外边界保留明确过渡；避免让每个内部模块感知多个版本。

在 Current Work 中只保留尚未迁移的实际消费者及下一项动作，不维护永久迁移台账。用户要求一次完成的开发仓库，直接合并所需内部变更。

## 删除包含支撑机制

检查废弃实现独有的配置键、注册项、命令、测试工厂、样本、文档锚点和构建命令。与其它能力共享的资源继续保留。删除操作以责任是否已经退场判断，禁止全仓命中同一字符串就机械删文件。

真实用户路径正常且已知消费者处理完成后结束。无需再为已删除的内部名称建立永久禁止检测。
