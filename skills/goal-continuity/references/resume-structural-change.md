# 恢复结构迁移主线

## 教学场景

用户要求统一存储，减少重复代码，并让 CLI 和 Web 都使用正式服务。实现已经迁移 Web，CLI 仍写旧文件。此时一个旧测试夹具失败，Agent 连续修了多项测试，开始为旧读取器创建兼容实现。

先回到用户结果：统一存储、迁移实际入口、减少负担。检查夹具是否仍对应支持的真实数据。若只是已淘汰实验输入，连同旧读取器测试退出；若对应真实数据，就在新的存储所有者处理所需迁移。旧测试是否变绿不决定整个任务方向。

## 保留能决定动作的状态

在宿主已有任务状态中保留以下当前信息：

```text
Objective: CLI 和 Web 共用存储所有者，删除旧双写及专属支撑。
Decisions: 正式数据由 StorageService 修改；内部旧接口已批准替换。
Current Work: Web 已迁移；CLI 仍写旧文件。下一步迁移 CLI，
              再删除旧读取器及专属测试，运行 CLI 保存后 Web 读取。
```

这些字段可以存在于当前会话、宿主目标或已有交接文件中。不要要求每次任务新建同名文件。输入格式本身不产生额外的更新仪式。

压缩恢复后读当前实际代码确认迁移进度。若 CLI 已被另一项工作迁移，就更新 Current Work 并处理真正剩余项。旧状态是接续线索，当前实现与有效需求决定行动。

## 把纠正变成下一项编辑

用户提醒“不要再维护旧结构”后，撤掉刚加的兼容实现，迁移仍在使用旧形态的消费者。不要把这句话抄进长期 AGENTS，然后继续给旧路径补测试。

状态中的已结束诊断及时移除，保留结果和仍影响后续工作的事实即可。编译错误、失败命令和曾经尝试过的方案需要时从实际记录查询，不占据每次恢复时的核心摘要。

## 新事实改变决定时直接更新

如果发现某外部客户端仍受支持，在那个真实边界新增迁移义务，并调整对应入口设计。内部消费者继续使用新所有者。若用户缩小范围或改变产品目标，Objective 随之改变，旧计划中无关工作停止。

约束具有对象和有效期。保存登录状态影响凭据相关操作，编译问题直接处理编译；发布审批影响外部发布，授权范围内的内部迁移继续完成。

## 用完成状态结束

CLI 和 Web 的真实路径都使用新存储，旧专属机制退出后交付。留下实际剩余阻塞时说明具体能力和原因。任务完整时，不再生成一轮目标对齐报告、永久进度日志或额外评审。
