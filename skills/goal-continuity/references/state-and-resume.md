# 能推动下一步的任务状态

## 三项状态的内容

Objective 描述用户结果，例如“管理界面保存设置后，运行中的服务使用新值，重启后仍保留”。Decisions 描述仍有效的选择，例如“配置服务拥有修改和持久化权，界面通过命令提交变更”。Current Work 指向产品缺口，例如“保存已接入，启动恢复仍读取旧文件；迁移启动入口并删除旧读取器”。

会话摘要保留这些信息以及恢复所需的路径。已结束命令、绿色测试列表和旧猜测留在原记录中。任务状态随能力和决定改变，避免每次运行命令都重写。

## 压缩后的恢复

阅读宿主摘要，查看负责当前能力的实现与最近变更，判断已经完成的行为。恢复已定的数据形状、实际接口及尚未迁移的消费者。信息冲突时回到用户要求和当前源码，替换错误摘要。相同的权威资料已在有效上下文时继续使用。

恢复记录只用于帮助下一步。读到了目标却仍在维护旧机制时，改变实际操作：退出旧夹具调查、完成调用者迁移、清除双轨，而不是再次复制目标文字。

## 必须交接时

独立子任务或换会话需要持久交接时，使用项目已有位置，覆盖当前有效状态。保留目标、决定、当前缺口、真实阻塞和必要文件入口。新状态替换旧状态；历史放在 Git 或原会话记录。

交接应让接手者能够开始下一项工作。不要让其先重跑所有历史命令、重新核验每个摘要或编写第二份交接报告。

## 失效决定退出

例如原计划使用文件缓存，实际并发写入需要事务存储。更新存储决定和调用契约，清理旧文件路径。原计划中围绕文件缓存的后续步骤同时删除，避免摘要把它们重新带回当前任务。
