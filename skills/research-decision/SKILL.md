# 研究与决策

## 明确这次研究要交付的认识

读取问题和已有有效决定，找到仍未解决的选择。选择任务给出决定，综述交代领域结构及证据，探索任务形成可用工作模型或能区分方案的实验。禁止把结果改成一张未来工作清单后结束。

常见偏移是先枚举风险，再追加更多检索和评估；搜到足够事实以后仍拒绝选择；把用户给出的解释拔高成更强主张，再花篇幅否定它。直接研究用户实际提出的命题。真实未知放在受影响事实附近，解释其改变的选择。

## 查决定所依赖的材料

工程问题从现行实现、运行时与官方接口读起。研究问题优先原始论文、数据和实验设置。用户自己的材料与外部资料分别归属；先前助手的说法需要回到原始来源核对。不要把搜索摘要、文章标题或发布日期当成完整研究结论。

公开资料可能更新，实际采用第三方 API 时核对对应版本。涉及私有仓库用已授权连接或本地资料；治理文本从本地技能读取。来源不通时保留已有内容，明确尚缺的具体事实，继续能够完成的推导。

## 比较有实质差异的路线

先确定目标能力与核心约束，再比较能改变责任划分、数据流、运行成本和维护轨迹的方案。将只有命名、封装或目录形式不同的选项合并。选择尺度见 [取舍方法](references/choice-and-uncertainty.md)。

不同方案的真实代价用任务条件描述：增加远程服务的运维和网络依赖，换取确有需要的共享状态或容量。不要靠“企业级”“更稳妥”“可能扩展”代替实际理由，也不要用一张权重任意的评分表制造决定。

## 调查到能够改变下一步

关键未知的答案会改变选择，就继续查。若测量能够解决它，采用最直接的实验：例如目标规模下的查询延迟、重启后的状态恢复或依赖的真实 API 行为。禁止先建设通用评测平台。

用户要求领域全景时，调查的广度本身属于成果；按需要覆盖真正不同的路线。发现新的结构性事实就更新工作模型，而不是机械执行旧搜索计划。

## 提交判断并保持力度

直接给出选择、决定性的依据及实现后果。区分已观察事实、引用结论和自己的推断，用它们承担各自的论证。禁止把确定的决定改回主观倾向或追加无关反驳。研究实例和来源方法见 [资料到结论](references/evidence-to-result.md)。

成果涉及架构时写清所有者、契约和数据流；涉及依赖时实际选择并说明集成位置，继续使用 [依赖选型](../dependency-selection/SKILL.md)。交付已要求的研究成果后结束。

选择搜索方案时，读取[本地搜索选型案例](references/local-search-selection.md)，把用户查询、维护责任和决定性实验连接到一个明确选择。
