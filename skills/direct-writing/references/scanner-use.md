# 使用语言扫描器定位文字问题

## 本地运行

从技能目录运行，显式指向要检查的文件或目录：

```bash
python scripts/check/governance_prose.py /absolute/path/to/document.md \
  --config scripts/.config/scanner.toml --format json --fail-on review
```

脚本使用 Python 3.11 及以上的标准库。扫描源码文字时增加 `--include-code`，实际代码语义仍由对应工具和人工阅读处理。默认 Markdown 扫描会跳过代码围栏、处理链接及引用位置；不要靠这些排除规则藏需要检查的自然语言。

## 处理每项命中

读取命中的完整段落及上下文。自己的防御性限定、重复自证和判断退缩，直接删改整项信息。必要的原始反例、规则定义或真实技术限制保留，并采用一个具体的局部豁免。禁止批量关闭规则或扩大到整类文件。

豁免用法见原脚本支持的 HTML 注释，作用于紧随的一项文字单元。必须写清实际保留原因。实例中的坏句式需要保留供学习，正文不要复制其表达习惯。

## 工具结果的使用

脚本输出位置、规则与固定说明，帮助找到需要阅读的地方。扫描零命中后继续按读者用途检查全文中的信息选择。UI 自证说明和作者身份变更可能没有任何受检词形，按实际作品处理。

## 按任务选择文件

检查实际修改或用户明确要求检查的文字。完整扫描任务要包括正文、示例及嵌在代码中的用户可见文案；引用和教学反例逐处保留用途说明。项目自身的扫描入口可按实际文件格式补充处理。禁止为了普通回复自动遍历整个仓库。
