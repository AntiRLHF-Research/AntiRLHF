# 子任务上下文和成果归属

## 一个完整任务简报

例如共享错误类型已经确定，可以并行迁移终端入口与管理界面。分别给出正式错误定义、各入口的用户行为、受影响源码和本次保留要求。目标是入口完整使用同一契约，交付包含实际修改及需要主 Agent 处理的共享变化。

当错误类型尚未确定时，先由一个任务设计所有者和类型，其他任务阅读实际结果后再迁移。禁止各自创造错误枚举后再由主 Agent 做多版本转换。

## 工作区的选择

只读调查可以共享同一源码快照。写入互不相干的文件且宿主支持并发时使用现有机制；共享文件频繁变化时改为顺序执行或明确的隔离工作区。必要的 Git 隔离见 [工作区](../../git-workspaces/SKILL.md)。

把“谁修改共同契约”说清即可。不要额外建立多层派工协议、任务评级和交接矩阵。

## 阅读结果的顺序

先读成果和实际变更，再读影响集成的发现。只看子代理“完成”声明会遗漏未迁移调用者；把其完整日志塞回主上下文又会冲掉当前设计。保留关键接口、未解决点和源码入口。

例如两个子任务都修了不同界面，但一个还缓存旧字段。直接迁移该消费者并清掉旧缓存形状。检查相关操作链后结束，避免为每个返回结果启动独立审查循环。

## 子任务终止与接续

超时或环境失败时取回已有结果，保留可用代码与已确认事实。根据缺口继续工作；新子代理拿当前有效状态，跳过已完成调查。用户缩小或改变目标时，结束失去用途的任务，避免继续消耗预算。
