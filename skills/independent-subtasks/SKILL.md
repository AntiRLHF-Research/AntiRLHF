# 独立子任务

## 按真实责任判断独立性

先找出任务间是否共享同一数据所有者、接口决定或可变文件。共同根因的故障先统一处理，强耦合的契约由一个责任人决定。独立领域和清楚输入输出的工作才拆开；禁止为了显得组织完整给每个小步骤启动子代理。

按 [独立任务方法](references/independent-task-method.md) 判断任务是否可分离，为每个执行者提供完整所需上下文，并明确共同契约的修改责任。

## 给足可工作的上下文

提供最终目标、当前有效决定、具体子任务、已知接口、必要源码入口和实际权限。说明需要返回的产物，例如变更代码、候选方案及决定性差异、可复用的故障定位。保留与子任务相关的需求，省去主会话的认错、日志和过时方案。

为跨模块任务分配完整责任，允许修改必需调用方。禁止因为随意限定一个文件而迫使子代理用包装绕过正确所有者。共享接口正在改变时先稳定该契约，再并行迁移独立消费者。

## 执行期间保持主线

主 Agent 持续处理自己的集成责任。子代理发现根本接口错误时，返回具体问题与可用改动，主 Agent 统一修改共享契约并通知相关任务。不要让每个子代理各造一个兼容版本。

不创建默认的“实现者—审查者—再审查者”链。需要独立判断时按用户目标调用相应专长，并把它的输出合回同一份实际产物。

## 整合到真正的所有者

阅读子代理实际变更和结果，处理相交文件、模型差异和遗漏消费者。整合后沿受影响用户路径验证接线；局部检查已覆盖的问题继续使用已有结果。整合方法见 [上下文与集成](references/context-and-integration.md)。

一个子任务失败就定位其真实阻塞，重新分配或由主 Agent 处理。禁止反复重派相同任务而丢失已经取得的结论。所有返回材料要进入代码、设计或用户要求的研究成果，完成后结束。

多个入口同时迁移时，读取[共享契约与独立子任务](references/shared-contract-before-parallel.md)，让同一模型有一个所有者，再分发能够独立交付的消费者工作。
