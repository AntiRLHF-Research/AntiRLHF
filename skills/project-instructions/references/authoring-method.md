# 编写完整、可发现的专项方法

## 从实际失败和所需能力开始

读取原始任务、实际行为和用户修正。将相近表现放进同一责任领域，保留各自具体触发情境。说明错误如何发生、怎样演化，以及正确结构和连续操作。禁止只写几个抽象口号，禁止用模型现编的夸张反例替代真实样本。

## 技能入口

名称表达具体任务，描述先说明正常开发中的用途，再明确要预防的错误倾向。用产品行为、技术对象和实际操作帮助发现，禁止把只能在故障发生后使用写成默认入口。正文直接告诉执行者怎样读材料、形成判断、改实现和交付。已完成的条件明确写出，避免执行者自行延长审查。

适用情境包含典型输入、症状和代码形状。复杂技术放在本地参考中，正文说明在哪个决定点读取哪一篇。不要强制所有任务经过需求、计划、执行、审查四个入口。

## 原文采用

从已有成熟方法和工程实现中选取完整有效章节，保留原句、代码和步骤。在原文上删除强制红绿、无条件门禁和重复验证，只补当前任务真正需要的语义。检查其引用是否仍会重新引入被删除流程。

英文原文和中文译文逐段对应。原稿与差异留给作者，最终执行稿供 Agent 使用。按实际分发范围集中保留同一来源的许可与采用信息，原有必须保留的版权头随源码保留。运行时直接使用本地内容。

## 纠错和深化

看同一情境下下一项动作与最终结构是否改变。规则能复述却照旧行动，就补充该分叉的具体判断、场景和操作，保持明确强度。不要再追加“每步解释遵守了什么”的义务。

机械扫描只定位部分语言形态。作者仍按读者、用途与实际行为判断整段。修改有用内容，删除重复制度，保持运行材料可直接使用。
