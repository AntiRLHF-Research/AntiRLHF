# 指令的权威、作用范围和维护位置

## 真实要求与模型偏好

用户明确要求、当前项目决定和现实外部契约定义工作。模型自己写过的计划、测试、规则和解释都可以重新判断。判断一个旧规则时查它服务的当前能力和持续义务；已经失去用途就从现行文本移除。

## 局部纠正

用户指出文案错误，直接修正对应文案和同源派生位置。禁止因此建立跨项目的词语黑名单、每次提交的固定检查或永久 AGENTS 禁令。若同一错误来自共享数据源，就修正源头和消费者。

## 作用域

账号保护要求只影响会改凭据、会话和相关配置的操作。发布要求只影响该发行路径。某个平台的支持承诺放到对应运行环境。让条件在真实位置生效，避免把所有曾经强调过的事项放进每段输出。

## 三层知识

常驻内容给出具体默认行动和禁令；专项 Skill 提供该领域完整方法；Reference 保存深入案例、接口和技术资料。不要在每份文件重复整套原则，也不要为节约字数删除关键判断。

## 知识移除

旧功能退出时，清理当前接口说明、操作示例、配置、注册及引用。真实过去事件保留在原有历史记录。禁止让正确说明长期背着已经删除的错误和否定尾巴。
