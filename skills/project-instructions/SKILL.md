# 项目指令维护

## 只记录真实持续要求

读取当前用户决定、项目实际行为、已有指令及其作用范围。长期内容应当帮助下一位 Agent 采取正确动作：关键项目事实、真实契约、必要操作与有效设计。禁止把自己的测试偏好、一次纠错和看似专业的流程写成永久制度。

模型已经熟悉且容易过量执行的通用做法不再强化。禁止初始化 AGENTS 时自动加入全量测试、逐步证明、所有任务必须审查或固定报告模板。

## 找到唯一维护位置

共同原则在常驻指令；领域方法在对应 Skill；详细技术在本地 Reference；项目特有事实在该项目自己的位置。相同规则维护一份语义来源，其他位置按需引用。禁止把多套原版与改编版流程一起加载再要求模型调和。

组织方法见 [作用域与权威](references/scope-and-authority.md)。旧计划和 Agent 输出没有自动保留权，当前目标改变时直接修正旧内容。

## 直接写可执行动作

写清遇到怎样的事实，读取什么，改变哪个所有者，怎样完成用户能力。禁止用“保持系统化”“避免过度工程”代替完整方法。适用的成熟原文直接采用，冲突条款在原文上修改，中文保持同样强度。

技能写法与摘编方法见 [编写与维护方法](references/authoring-method.md)。运行正文自包含或指向已安装的本地资料，禁止要求 Agent 联网读取私有研究仓库才能开始普通工作。

## 删除失效和越域规则

局部错误在原处修正，删除错误纪念和派生警告。明确错误决定已经更新，就连同其冗余条件、旧示例和过时调用修改。真实历史记录归发布或研究资料。

约束只作用于相关对象和期间。保护登录状态影响凭据操作，不能演化为每次 lint 后检查登录的规定。状态记录只保存当前工作，不扩成长期日志。

## 检查实际可用内容

读取修改后的指令及引用，确认执行者获得一个连贯方法，移除通向已淘汰强制流程的跳转。对语言进行定向扫描和上下文编辑，实例与原文留在清楚位置。禁止让治理规则再产生逐步遵规表或周期性反省。

交付现行可用指令。用户要求分析而未授权修改时，给出具体问题和调整方向，保持任务范围。

初始化或更新项目指令时，读取[项目事实与临时纠正](references/maintain-instructions-without-drift.md)，只留下真实持续要求，并把专项方法放回本地知识所有者。
