# 批量导出：授权贯穿整个用户路径

## 教学场景

接口接收一组记录 ID 并创建导出任务。单条查询会检查权限，批量实现却直接按 ID 查询数据库；后台任务用系统账号执行，生成的文件又通过公开地址下载。三个局部组件都能工作，组合后越过了原有授权规则。

从“谁请求、读取哪些对象、执行时身份是什么、谁能下载”追踪全链路。认证使用项目既有机制，授权由负责数据访问的领域操作执行。基本方法参照 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)，具体权限仍由产品定义。

## 同一查询权威服务单项与批量

查询从可信身份和租户上下文开始。对明确 ID 列表，将授权过滤纳入查询或统一领域检查；对“全部记录”，通过同一授权范围读取完整分页。客户端传来的租户字段不能替换登录身份。

混合了允许与不允许的 ID 时，产品应选定整体拒绝或显式部分结果。错误信息避免泄露不可见对象的内容。不要静默丢掉无权限项后返回“全部导出成功”。

CLI 的管理员能力来自实际运行身份和权限，不能因入口叫 CLI 就跳过规则。后台 worker 同样不凭自己的高权限扩大用户请求范围。

## 任务跨时间后的权限

持久任务保存发起人和目标范围，以及恢复操作真正需要的信息。发起时检查权限；执行时按产品约定重新校验当前授权或使用已批准的受限执行凭证。账号已禁用、成员资格已撤销时，按当前策略终止并给出可理解状态。

直接把用户长期访问令牌存进每条任务记录，会扩大凭据暴露范围。复用宿主的秘密管理与凭证引用机制。日志保留可关联的任务身份，清除授权头、原始令牌及不必要的个人信息。

## 结果也有访问规则

导出文件归属请求任务及用户或组织，下载端点再次验证访问权限。需要分享链接时，采用现有受限、可过期的分享能力，明确分享对象与有效期。结果过期或被清理后返回实际状态，不通过新建文件绕过权限。

页面展示任务状态、可下载结果或具体失败原因。删除“已经严格验证权限”等自我说明。安全要求落实在真正的边界。

## 高价值检查与完成

检查两个用户跨租户访问、混合权限列表、执行前权限撤销以及结果下载权限。这些位置可能独立失效，应分别保护。认证库的加密与令牌算法由成熟实现承担，项目只验证接线及业务规则。

任务完成后继续正常产品开发。一次权限修复不自动产生全仓安全制度、普遍审批或每轮凭据状态报告。
