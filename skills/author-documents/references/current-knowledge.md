# 维护当前正确知识并清除墓碑

## 一项事实有一个维护位置

配置字段归正式 schema 和相应说明，行为归现行实现与契约，历史事件归发布记录，研究观察归研究材料。其它位置通过引用、生成或明确同步关系复用。不要为一次纠错再建立一个平行事实目录。

## 错误直接退出现行文本

用户纠正接口名称、配置方式或架构决定时，在对应位置写入正确内容，删除原错误及其派生说明。禁止把纠正历史改写成永久括号、警告或否定式纪念。

例如开发指南仍指向已删除的内部入口，直接替换操作及示例。真正需要给外部用户说明迁移的版本变化放在迁移指南，当前接口说明保持清楚。

## 规格随设计更新

用户批准的新责任分工已经替代旧设计，就修改现行规格、示例和相关图示。旧规格的文字无法阻止新的架构判断。实现发现原设计不适用时，把决定和契约同步修正，继续当前目标。

## 长期指令的维护

创建或修改 AGENTS 和 Skills 时使用 [项目指令维护](../../project-instructions/SKILL.md)。仅有临时错误、模型偏好或一次用户纠正，不扩写为跨任务禁令。指令应帮助下一个 Agent 作对下一项选择。

## 删除与导航

移除功能时清理现行导航、锚点、生成来源和被维护译文。历史档案保留在其位置。修改涉及链接时检查实际本地目标，禁止为了“文档完整性”在无关任务中维护全仓索引台账。
