# Git 工作区

## 按本次工作需要选择隔离

读取用户指定的分支与工作区方式。普通可逆修改在当前允许的工作区完成；独立并行写入或用户要求隔离时使用工作树。先识别宿主已经建立的隔离，防止再创建一层工作树。

在改动前查看当前分支、已暂存、未暂存和相关未跟踪文件，保留无关用户工作。不要用 reset、clean 或完整暂存把不属于本次工作的内容卷入交付。

## 使用现有宿主和 Git 能力

使用 [已有隔离识别](references/existing-isolation.md) 中摘编的 Git 方法，区分普通仓库、linked worktree、submodule 和 detached HEAD。宿主已经管理工作区时继续使用其位置和生命周期。明确需要新隔离时优先使用宿主工具；工具缺失时使用原生 Git。

Git 命令只回答本次操作的问题。不要在创建工作区前自动追加全仓测试、许可证审计、快照和恢复演练。创建与清理的实际操作见 [工作树生命周期](references/worktree-lifecycle.md)。

## 保持源码和环境一致

新工作区使用项目既有依赖安装与启动方式，配置和凭据沿已有安全来源提供。只修复阻断本次工作的问题；禁止复制秘密到仓库或为每个工作区制造独立环境管理框架。

分支上的成果围绕用户需求。原有用户改动留在原位置，子任务结果按实际文件和契约整合。

## 按所属关系清理

提交或合并用户要求的成果后，只移除本次创建且结果已经保存的工作区。先确认当前路径和未提交工作，再从工作区外执行清理。外部创建的工作区和其他分支由其所有者管理。

如果 Git 拒绝操作，阅读具体原因，处理文件占用、未提交变更或实际冲突。禁止直接加 force 覆盖问题。完成用户要求的分支或工作区操作后停止。

用户已暂存内容或要求分层交付时，读取[提交、暂存与工作区](references/index-and-working-tree.md)，按现有索引保存用户选择，保持后续改动的边界。
