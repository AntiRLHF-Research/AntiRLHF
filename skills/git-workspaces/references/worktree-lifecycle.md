# 工作树创建、使用与清理

## 已有用户工作

用 `git status --short` 看工作区变化，按本次任务实际路径读取 diff。明确暂存区里哪些属于用户已有工作。新修改按文件或 hunk 暂存，不把无关变化一并提交。

如果当前任务无需隔离，保留当前工作区即可。需要并行隔离时，读取用户指定的位置和分支。新目录放在已知合适的父目录中，避免嵌套到源码或其他工作树。

## 原生 Git 操作

以下命令用于已决定的独立工作区，替换路径和基准分支为真实值：

```bash
git worktree list --porcelain
git worktree add -b feature/import-records ../project-import main
```

在新工作区运行项目正常的安装与启动命令。工作树共享 Git 对象；依赖目录与运行时配置按项目现有方式处理。项目内工作树目录需要被忽略时，更新实际忽略规则即可，提交与本次工作统一安排。

## 合回工作

先完成本次行为和相关检查，再按用户选择的方式合并、提交 PR 或保留分支。按真实起点看差异；多个提交的任务从实际基准比较。具体发布使用 [集成与发布](../../release-integration/SKILL.md)。

## 清理

离开待删除工作树，再检查是否有未保存的任务成果。使用 `git worktree remove ../project-import` 删除自己创建且已完成用途的工作树。目录仍有修改时停下来处理这些真实文件，禁止用强制删除跳过。

不要移除宿主拥有的隔离环境。失败分支含有可用诊断与改动时保留，直至它们已进入有效结果或用户决定丢弃。
