# 记录有用事件并保留上下文

## 记录位置

请求入口建立操作上下文；领域事件描述已发生的业务变化；失败由理解其处理语义的位置记录。示例中的“任务导入失败”应带任务身份、已分类原因和必要的外部请求标识，避免完整上传内容和密钥。

日志输出与配置使用现有框架。Python 的 `logging`、项目已用的结构化日志库，或其它语言成熟日志接口都可以承担机制。业务代码传递结构化字段，禁止各模块拼出不同格式的字符串。

## 上下文传播

异步请求与后台任务需要关联时，使用运行时上下文或 OpenTelemetry instrumentation。跨进程传播采用标准载体，在真实边界注入与提取。不要让每个库各自重新生成一套请求身份。

传播内容只包含必要关联信息。用户输入和认证材料不得因便利进入全局 baggage。记录者看见的是与当前操作相关的上下文，避免把无关会话信息放进每一行日志。

## 错误记录的重复

下层抛出保留原因的错误，上层在完成处理时记录。已经记录并转成明确结果的错误不在每一层再打印相同堆栈。调试需要额外层信息时，针对当前疑点临时观察，解决后清理。

## 程序输出与用户输出

CLI 的机器可读结果留在 stdout，诊断放 stderr；交互状态按实际工具约定呈现。页面给用户操作和可理解结果，日志保存开发所需信息。禁止把全部诊断字段和验证经历直接塞到用户屏幕。

技术参考：[OpenTelemetry 上下文传播](https://opentelemetry.io/docs/concepts/context-propagation/)、[Python logging](https://docs.python.org/3/library/logging.html)。
