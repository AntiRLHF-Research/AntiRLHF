# 接通真实模型和外部能力

## 先读实际集成条件

核对项目已有 SDK、配置来源、凭据注入方式、目标服务与用户授权。成熟 SDK 提供协议、序列化、连接和错误类型时直接采用。禁止为了避开依赖自写全部协议，也禁止为了显得通用先造多提供方注册框架。

## 真实调用的路径

在负责外部能力的边界创建客户端，复用应用配置与生命周期。领域调用传入需要的业务内容，读取正式返回结构。流式响应逐步交给实际消费者，正确处理结束、取消和提供方错误。

仅打印一段假模型文本，或者在测试中用 Mock 返回成功，不能交付用户明确要求的真实模型能力。完成授权范围内的实际调用，并沿 UI 或 CLI 查看最终结果。凭据或额度缺失时报告具体阻塞，禁止伪造回执。

## 费用与授权

使用用户明确允许的账户、服务和预算。验证选择低成本、能够回答接线问题的真实请求。禁止为证明调用可靠性而反复付费请求；有外部副作用的操作在实际授权范围内执行。

只把非敏感的配置来源和错误类别呈现给用户。密钥、完整认证头和私有内容不写入提交、日志或示例。采用框架与平台已经提供的秘密管理能力。

## 原型与正式能力

用户明确要求原型时，输出可运行的原型并描述它实际提供的功能。用户要求产品实现时，继续完成持久化、错误和资源生命周期。不要用“先给一个初步实现”替代已经授权的完整工作。

外部调用测试完成后，把有效代码留在正式所有者，移除临时调用脚本和硬编码凭据路径。真实接线已经确认，就回到产品其它缺口。
