# 摘要功能：从入口到真实模型结果

## 教学场景

用户要求对选中文档生成摘要，并能查看历史结果。界面按钮已经存在，服务端返回固定文本，单元测试全绿。任务要求的是接通真实提供方并保存可用结果。

先追踪文档选择、权限、文本读取、提供方客户端、模型参数、流式结果和保存位置。检查项目已有 SDK、配置与密钥管理，优先使用正式提供方 SDK。不要为一个模型调用创造新的通用 Agent 框架。

## 明确结果及其身份

一次摘要关联文档及其内容版本、操作者、所用配置和结果状态。用户在生成期间修改文档时，已运行任务仍对应启动时的版本；显示结果时让用户辨认是否来自旧内容。重新生成是一项新的操作。

领域状态可以是等待、运行、完成、失败和取消，字段依据产品行为设计。成功内容与部分流式内容分开保存。占位文本只用于用户明确要求的原型，不进入正式成功路径。

## 先完成一次真实调用

从实际入口读取授权文档，取得有效模型配置和凭据，发出请求，把真实返回传到页面或 CLI。若调用会产生费用，使用用户已经授权的提供方和范围；缺少凭据时明确说明该集成阻塞，继续完成不依赖凭据的已有授权工作。

测试环境的 Mock 可以验证错误分支，但正式功能仍需要接到真实 SDK。禁止把“连接配置已写好”报告成模型已经调用成功。

## 流式显示与完成状态

先展示已有内容，增量到达时追加，保留取消入口。中途断流时保存或呈现部分结果，并说明当前失败及可用恢复操作。正式完成状态由提供方完成信号、必要解析和保存结果共同决定。

取消从 UI 传到任务所有者，停止后续读取并释放响应。提供方是否停止计算取决于它的接口；若远端仍可查询，保留操作身份。旧任务晚到的消息不得覆盖用户已经发起的新任务，展示使用对应请求或作业身份。

## 保存、重启和再次读取

结果写入成功后再报告已保存。历史列表从正式存储读取，详情可还原所关联的文档版本。任务运行状态需要跨重启恢复时，采用项目已有任务机制，明确恢复、失败或取消策略。

从选择文档到生成、保存、刷新、再次打开走一遍实际路径。然后处理取消、提供方拒绝和保存失败这些实际边界。不要停在 SDK Helper 的测试通过，也不要因某个无关旧测试失败把任务改成全仓测试治理。

## 完成后移除占位通道

删除固定摘要返回、演示专用成功标志和已经替换的模型包装器。保持一个真实生产调用链。用户只要求摘要时，交付这个完整能力；模板市场、模型排行榜和自动评测面板留给真正的产品需求。
