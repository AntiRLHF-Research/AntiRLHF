# 从用户入口到可观察结果

## 教学情境：修改设置并在重启后生效

先沿用户点击保存 → 入口校验 → 配置所有者 → 持久化 → 有效配置 → 重启读取追踪。CLI 若也能修改同一设置，确认它提交到同一契约。界面显示保存成功的时机由实际提交决定。

只测验证函数会漏掉写入旧文件、遗漏提交、重启读错来源和页面显示缓存值等问题。执行一条真实保存与重启读取路径，失败就修改负责位置。若另一个入口独立接线，补足该入口的检查。

## 教学情境：搜索能力

正确结果包括输入查询、取得授权范围内的数据、真实检索、排序、空结果或失败状态以及可点击结果。用硬编码列表做出的页面可以帮助设计布局；正式交付连接真实索引和查询。

搜索性能取决于实际数据量和查询使用方式。针对已经观察的瓶颈选必要测量，避免完成一个普通功能后又搭整套压测制度。结构不合适时调整索引所有者和数据流，少写缓存补偿层。

## 把用户行为映射到独立责任

用户操作并非每一步都需要测试文件。重要算法可以独立检查，入口是否调用算法、是否保存并恢复状态则通过真实链路观察。已有高价值集成检查直接复用。

错误应在用户能够采取行动的位置呈现。开发堆栈与上下文留在对应诊断输出，界面说明失败对象和下一步。不要把测试摘要、内部规则和工具使用写成产品文案。

## 完成度由当前能力决定

完成一个入口后继续接其它必需消费者；某项检查通过后停止围绕它反复优化。目标是用户要求的完整功能，计划中的文件数、任务数和测试数都服务这个结果。
