# 完整能力交付

## 把最终能力放在工作中心

从用户要求确定完整操作链，读取入口、负责规则的模块、状态修改、外部调用和结果呈现。已有设计可以使用就推进；实际发现责任错误就修正它。禁止只完成一个内部函数，然后通过大量测试把它当成产品交付。

用户只要设计或反思时交付对应成果。这里用于已经授权的实施工作，内部可逆改动直接完成，外部发布、真实数据删除和额外费用依实际授权处理。

## 先接通一条真实路径

选择最有代表性的用户操作，让它经过真实配置、正式业务操作和实际依赖到达结果。需要调用模型、数据库、外部服务或系统设备时，连接真实实现。模拟对象服务开发隔离，最终用户要求的实际能力必须接通。

实现过程中优先完成这条纵向路径，再推广到同类入口。禁止先造大量空接口和假返回，最后才发现资源、错误和状态契约彼此不合。

## 接好状态和错误

明确何时成功、何时仍在处理、何时失败，以及重试或取消会产生什么后果。将结果通过 CLI、页面或 API 的正式输出交给使用者。持久化和重启属于要求时实际读取恢复状态。

外部调用的授权、费用和凭据见 [真实集成](references/real-integrations.md)。产品操作与多入口贯通见 [从入口到结果](references/user-paths.md)。

## 完成关联消费者

共享能力改变后，迁移其它入口、后台任务和注册路径。依赖选定后使用其正式能力，删除临时重复实现。反复出现配置、网络和错误分歧时调用对应基础技能，解决源头，不为每个入口写补偿。

检查已经回答局部问题后，继续下一项未完成产品能力。若真实阻塞暂时阻止外部调用，准确报告阻塞并完成其余可独立工作；禁止伪造成功、把 Mock 结果标为真实集成或只留下一个“稍后接入”的空壳。

## 交付并停止

按原始目标查看真实入口、关键操作结果和仍未解决的缺口。结果完整就简述具备的能力和必要使用信息。已知尚未完成就继续，避免以询问是否继续提前结束。禁止在交付之后自行追加审查 Agent、验证矩阵和收尾归档。

实现依赖模型的产品功能时，读取[从入口到真实模型结果](references/model-feature-path.md)，贯通提供方调用、取消、状态、持久化与用户呈现。
