# 有效配置、更新和迁移

## 教学情境：多个设置入口

页面调用接口保存，CLI 修改文件，后台任务缓存另一份对象。用户看到的值取决于从哪条路径读取。先选出有效配置和写入权，在线编辑经过该所有者提交。离线修改确属产品能力时，定义文件如何被启动加载以及与运行状态的关系。

## 更新时的状态转换

先验证候选值，再以项目已有事务或原子写方式保存，随后切换有效快照。需要重建客户端的字段在相应生命周期负责人处重建，并关闭旧资源。配置提交失败时保持此前有效状态，返回具体失败原因。

多条配置必须一起生效时按整体快照提交。禁止让页面逐字段写入后由多个消费者观察中间组合，除非产品明确允许这种逐项生效方式。

## 不增加无用热更新

启动读取已经满足产品需求，就说明修改后重启生效。不要给每个设置加文件监听、事件订阅和回滚状态机。运行时更新是现实能力时，完成一次真实修改到实际消费者的生效路径。

## 清除旧形状

迁移硬编码和私有解析时，删除旧默认值、废弃配置键、私有环境前缀及当前文档中的旧设置方法。原有用户配置需要保留时在配置输入边界处理一次迁移。禁止内部各层同时接受所有旧键。

## 有价值的检查

检查优先级冲突、非法输入、提交失败后的有效值以及重启恢复。普通字段的存在性不逐个测试。实际连接或任务使用新值后，继续产品剩余能力。
