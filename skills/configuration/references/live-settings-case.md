# 配置快照切换：保存、生效和资源释放

## 教学场景

应用允许用户在运行中修改远程服务地址与连接参数。页面写数据库，后台任务各自读取环境变量并缓存客户端，导致页面显示新地址而实际请求仍发往旧地址。产品已经明确要求这些设置即时生效。

先把配置读取与修改集中到配置所有者。默认值、部署环境和用户设置的覆盖顺序确定在一个位置；业务模块只接收已验证的有效配置。读取优先级与类型处理复用[配置来源](sources-and-types.md)中的成熟实现。

## 根据字段影响安排生命周期

同一设置面板可以包含不同生效方式。显示语言可以直接更新界面资源；远程服务地址需要替换对应客户端；数据库文件路径可能约定重启生效。按真实消费者分类，避免给每个字段都搭热更新订阅。

页面读取配置时一并获得版本身份。提交修改携带预期版本，过期编辑返回冲突，避免两个页面互相覆盖。密钥输入只承担写入，新值以外的界面继续显示“已配置”或脱敏状态。

## 切换流程承担实际失败

下列顺序是单进程应用的控制关系：

```text
校验候选配置
→ 准备候选客户端和所需资源
→ 检查当前版本并保存候选值
→ 发布新的有效快照和对应资源
→ 等待旧请求结束，关闭旧资源
```

资源准备失败时关闭已创建的候选资源，保持旧快照。保存失败时同样丢弃候选资源。持久化已完成而进程在发布前退出时，重启从保存值重建资源；启动失败需要返回明确原因。不要对数据库写入与任意外部服务连接承诺一项跨系统原子事务。

配置提交顺序由现有更新锁或串行执行机制统筹。快速连续提交时，较旧候选资源不得覆盖较新版本。任务在开始时取得一份一致快照，正在执行的任务按既定策略完成；新任务使用新快照。禁止模块独立订阅后自行决定混合新旧字段。

## 保留一个可见事实

产品支持重启生效的字段时，页面分别显示“已保存，重启后生效”和当前有效值。产品要求即时生效的字段，在资源发布成功后才报告已应用。删除模型写入的“已完成全面校验”等内部自证文案。

## 迁移与实际使用

迁移页面、CLI 和后台任务到正式读取与写入契约，删除各处环境变量解析、重复默认值和私有客户端缓存。用一次真实配置修改观察下个任务使用新地址；在候选地址无法连接时确认原任务仍按选定策略运行。只验证影响状态切换的独立失败，避免给所有简单字段各造一组测试。

产品只需要启动时读取配置时，采用启动校验与重启生效。该任务无需上述在线切换机制。
