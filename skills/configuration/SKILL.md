# 配置

## 找到全部读写来源

沿当前能力读取参数怎样进入系统：命令行、环境、文件、数据库、UI 和默认值。找出谁校验、谁持久化、谁持有有效值、何时刷新。相同参数在多个模块分别解析或拥有默认值时，回到正式配置所有者统一。

禁止到处硬编码地址、路径、超时、开关和数值，再逐处修改。也禁止把所有业务数据都包装为万能配置系统。技术运行参数、用户偏好和领域状态按实际生命周期归属。

## 定义正式配置模型

以已有框架或成熟设置库承担解析、类型和来源合并。明确名称、单位、合法范围、默认值、敏感性与覆盖顺序。缺少关键配置时给出能够处理的错误，禁止静默回退到另一个环境。

配置加载和类型示例见 [来源与类型](references/sources-and-types.md)。需要改来源优先级时在一处决定，所有入口使用同一规则。

## 选择生效方式

启动期配置在应用组合根加载并注入需要的组件。运行时可修改配置明确由谁提交、何时成为有效值、持久化失败如何反馈，以及旧客户端怎样释放。读取者获取正式有效值或不可变快照，禁止持有各自可修改副本。

离线编辑与热更新方法见 [有效状态与迁移](references/effective-state.md)。简单项目只需启动读取时就采用该方式，禁止无需求引入监听器、事件总线和热重载框架。

## 迁移实际消费者

将每处环境读取、常量和私有解析改为正式契约，修改字段引用及相关使用说明。处理资源构建者需要的新参数，删除旧默认值、转换函数和兼容键。真实用户配置有旧字段时，在输入边界一次迁移。

机密通过现有秘密管理或受控环境注入，不写入仓库和示例。日志只呈现诊断需要且允许暴露的有效配置；不要输出完整设置对象。

## 从用户操作确认结果

实际改变设置，观察目标行为和要求中的重启结果。各入口涉及同一值时确认它们共享有效状态。只保护来源优先级、校验和更新事务等有意义行为，禁止逐字段创建浅层存在性测试。

配置语义统一、消费者迁完、旧路径退出后结束。当前用户指南说明怎样设置和何时生效，省去迁移自证和内部实现说明。

同时提供设置页面和后台消费者时，读取[配置快照切换](references/live-settings-case.md)，区分已保存值、当前生效值与资源更新。
