# 传输与错误

## 追踪真实调用链

从用户操作找到外部请求的创建位置、配置来源、认证注入、资源释放及错误处理。识别同一机制在哪些模块重复。不同协议或独立提供方保留真实边界，同一底层机制收敛到已有客户端或明确所有者。

禁止每个功能再造请求包装、私有错误枚举和兼容分支。统一方案需要修改上游接口时直接修改，迁移实际调用者并删除旧路径。

## 选用成熟协议实现

使用项目已有客户端或提供方 SDK 的连接池、流式读取、代理、TLS、超时和异常类型。应用生命周期创建并关闭共享资源。业务模块获得所需客户端或操作，不在每次调用中临时构建另一套网络栈。

客户端组织见 [客户端与错误边界](references/clients-and-errors.md)。只有真实提供方语义差异需要时才建立适配边界，禁止为了“统一”给成熟 SDK 每个方法套转发层。

## 统一失败的语义所有权

传输层区分连接、超时、协议和响应错误；提供方边界解释对方错误；领域所有者解释业务冲突和权限。对外入口映射为用户或调用者需要的结果。原始原因保留供诊断，禁止多层各改写一次字符串或把所有失败吞成空值。

稳定错误类别供程序分支，人类文案按使用者任务组织。不要让业务代码靠字符串包含某词猜失败原因。

## 决定重试和取消

读取操作是否幂等、超时后结果是否未知、SDK 是否已经重试以及总时间预算。重试由一个责任位置控制，禁止调用方、SDK 包装和队列同时倍增请求。处理方法见 [重试、预算与取消](references/retry-and-cancellation.md)。

取消沿实际调用链传播并释放资源。禁止把取消吞成普通失败再重试，禁止通过无限延迟和 fallback 掩盖错误。

## 完整迁移和验证

把请求配置、错误表示和调用契约迁到全部实际消费者。删除旧网络实现、私有枚举和转换器，更新使用说明。通过真实入口观察成功、必要失败与取消；项目只验证自己的接线和契约，成熟客户端内部行为由上游承担。

交付使用者能够完成的能力。不要把传输规则、工具名称和校验经历直接放进 UI。

外部调用涉及重试或结果不明时，读取[操作结果与恢复](references/operation-outcomes.md)，把传输失败、领域拒绝和未知提交结果分别处理。
