# 重试、操作预算与取消

## 先确定请求是否可以重发

查询通常允许重试，支付、创建资源或发送消息可能已经产生副作用。网络超时后操作结果可能未知，先依据协议的幂等键、状态查询和提供方语义处理，禁止盲目再次执行有副作用的请求。

检查成熟 SDK 已有重试和超时配置。把产品允许的总预算交给一个位置控制，避免 SDK 重试三次、业务层再三次、任务队列再三次的放大。重试等待使用成熟库支持的退避和限流响应处理。

## 时间预算

区分建立连接、读取、写入和整个用户操作的截止时间。每次尝试都要留在整体预算内，取消也应立即传递。默认值从统一配置来源读取，禁止每个模块各写一份常数。

## 条件等待

等待后台状态就观察实际事件或状态，使用已有等待工具并设截止条件。禁止通过增加固定 sleep 隐藏竞争。真实的防抖或节流时间属于功能契约，按该时序检查。

## 取消与资源清理

用户取消、请求断开或应用关闭时，把取消传给正在运行的请求、流和后台任务，关闭响应并释放资源。异常捕获保留取消语义。禁止宽泛捕获所有异常后统一重试。

## 教学情境：模型流式响应

用户停止生成后，页面中止流式读取；服务取消上游请求并停止写入，任务状态反映已取消或外部已经完成的真实结果。不得在取消后自动重新请求一份回答，也不得只隐藏 UI 而让无用上游调用继续消耗费用。

检查实际取消链与必要失败，随后完成用户体验。实现中更改了生命周期时交由 [异步任务与生命周期](../../async-lifecycle/SKILL.md) 处理资源归属。
