# 跨平台

## 从真实目标平台出发

读取用户要求支持的系统、运行方式和部署环境。追踪涉及文件、进程、网络、编码和系统能力的真实操作。现有平台抽象已经可用就复用，禁止为了想象中的所有系统新建通用兼容框架。

同一平台判断散落多个模块时，集中到承担该系统能力的边界。业务模块调用表达真实能力的契约，不自行拼路径、识别 shell 或猜环境。

## 采用运行时与成熟库

路径用标准路径 API，进程参数用已有启动接口，配置目录使用平台或现有库，编码按真实协议处理。技术方法见 [路径和进程](references/paths-and-processes.md)。禁止通过字符串替换斜杠实现完整路径处理，也不要把不可信参数拼进 shell 字符串。

## 明确差异的语义

大小写、符号链接、文件占用、权限、换行、可执行文件和时间格式等差异，只有影响当前能力时才处理。选择实际支持的行为，失败返回具体原因。不同平台确有不同实现时，放在该边界，内部保持统一业务契约。

实际平台选取与验证见 [平台适配与迁移](references/platform-integration.md)。不要把源码里每个分支都做成插件。

## 迁移重复路径

把硬编码目录、私有平台判断和重复命令构造迁到正式所有者。更新消费者、配置和说明，删除旧分支及其专属测试。旧平台没有实际支持义务就按当前要求删除，不为了历史保留一套 fallback。

## 运行所要求的平台行为

在可用的目标环境执行受影响路径，检查真实文件与进程结果。未具备的环境在相应结果处说明，禁止虚报跨平台通过。项目已有 CI 或平台验证直接复用，不为普通局部任务创建新的系统矩阵。

完成当前平台能力后交付，用户文档写实际可用操作。不要在每段话后追加所有想象平台的免责声明。

桌面与 CLI 需要调用外部程序时，读取[外部工具的跨平台边界](references/external-tool-boundary.md)，统一程序定位、参数、路径、输出和退出语义。
