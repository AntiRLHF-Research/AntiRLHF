# 按真实平台要求完成适配

## 教学情境：桌面导出目录

应用在开发机器上将文件写到固定用户路径。换一台机器就失败，模型在每个入口分别增加系统判断和备用目录。

把导出目录作为正式配置或用户选择，使用标准路径能力。权限与写入失败由文件操作边界报告，CLI 和 UI 处理对应的用户提示。配置目录的系统默认位置采用成熟平台库，实际输出路径由产品行为决定。

## 适配边界

领域操作表达“保存导出文件”“打开本地资源”或“监听目录变化”。不同系统实现放在该能力内部。不要让所有业务模块知道 Windows、Linux 或 macOS 的命令细节，也不要把不相关能力全塞进一个平台万能类。

## 迁移旧分支

按真正使用该能力的消费者迁移，更新参数和错误契约。删掉被替代的脚本、硬编码路径和重复平台判断。已不支持的内部旧路径不再通过 fallback 维持。

## 检查与交付

实际目标环境可用时执行用户路径。项目已维护平台 CI 时使用它，不额外增加重复流程。只报告实际观察到的环境结果；某一必需平台缺环境时说明该项缺口及所需资源，继续完成可以进行的工作。

用户文档给出平台对应的操作与结果。内部适配方式和验证经过留在开发所需位置，省去向最终使用者报告实现尽职情况。
