# 批量导入：状态、恢复与信息层级

## 教学场景

用户上传一个文件，将其中记录导入资料库。页面原来只有上传按钮和成功提示，后端可能需要较长时间解析；取消、部分失败和重启后查看结果都没有接线。Agent 容易先加一圈进度卡片和“经过严格验证”的说明，实际任务仍然不完整。

从用户要完成的动作开始：选择文件、确认导入方式、知道是否仍在进行、处理失败、查看结果。逐个接通这些行为及其数据来源。

## 状态必须来自实际所有者

| 实际状态 | 界面主要内容 | 可用操作 |
| --- | --- | --- |
| 未选文件 | 文件选择入口和真正的格式要求 | 选择文件 |
| 已接收、等待处理 | 文件名与排队状态 | 按产品能力取消 |
| 处理中 | 当前可获得的实际进度 | 查看进度或请求停止 |
| 全部完成 | 成功导入数量与结果入口 | 打开导入记录 |
| 部分失败 | 成功与失败数量、具体可处理原因 | 下载失败记录或按真实能力重试 |
| 结果未知或连接中断 | 保留任务身份和当前已知状态 | 查询原任务 |

后端没有总量时，不生成假的百分比。请求取消后，界面保持“正在停止”直至任务所有者确认终态。用户关闭面板与取消任务是不同动作，分别实现。

## 区分必要信息与施工说明

文件大小限制、需要的列名和错误行号会影响操作，保留在合适位置。内部解析库、测试次数和“遵循所有约束”描述开发过程，从页面删除。统计口径确实改变结果解释时给出具体说明；不要为每个数字追加一段对潜在质疑的答辩。

真实人工编辑对照见[界面信息取舍](content-and-observed-edits.md)。其中保留了帮助读者判断数值方向的说明，删除了与实际使用无关的制作和边界自证。迁移这个信息取舍方法，不把截图里某个工具名变成全产品关键词黑名单。

## 布局跟随操作主次

主要动作放在当前状态最需要的位置。完成结果和失败处理有清楚层级，不把所有状态平铺成同等大小卡片。字段标签、按钮和反馈使用一致动作名称。焦点、键盘操作、加载状态和错误关联使用现有组件的可访问性能力。

按钮禁用时，只有实际原因会影响用户下一步才解释，例如文件尚未选择或当前账号无导入权限。不要给每个禁用按钮附上开发者规则说明。

## 真实操作贯通

选择文件后提交正式任务，依据返回任务身份读取进度，完成后打开真实结果。刷新页面仍能找到任务时，从正式存储恢复；产品只支持当前会话时明确其实际行为，避免显示不存在的历史入口。

走一次完整导入与一个实际失败恢复场景。观察文字截断、长文件名、空结果和部分失败的排布。截图用于看见页面，代码和网络路径用于确认动作；两者按当前问题配合使用，不额外制造视觉审计流程。
