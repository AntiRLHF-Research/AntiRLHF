# 用户交互与内容

## 从实际使用者的视角组织界面

读用户要完成的操作、现有产品语言和真实可用能力。确定页面或命令的主要动作、对象、状态和下一步。开发委托者提出的规则落实到代码和数据，界面向最终使用者呈现结果。

禁止把使用了什么工具、遵循了什么约束、校验了多少次和内部方法边界当成产品文案。说明一个事实会改变使用者的操作或理解时，把它放在最相关位置；无用途的制作过程说明整项删除。

## 建立连续操作链

串起入口、输入、提交、处理中、成功、失败、取消和返回。按实际功能处理必要状态，不因模板包含某状态就制造功能。表单、按钮和命令名表达实际动作，完成反馈沿用同一术语。

交互方法见 [任务和状态](references/tasks-and-states.md)。现成组件与平台可访问性能力优先复用，不另造控制系统。

## 按信息关系设计层级

选择能表达内容关系的布局、分组和导航。编号仅用于真正顺序，卡片用于独立内容单元，标签用于帮助识别信息。禁止给每个段落机械加 eyebrow、卡片、流程编号和无关解释。

先用真实内容建立结构，再确定视觉处理。遵循用户已定风格与品牌，保留必要的可访问性、键盘操作和窄屏行为。

## 直接编辑用户可见内容

阅读完整段落及其页面位置，判断信息供谁使用。删除向委托者展示工作过程的文字，保留操作事实、有效状态和帮助使用者理解的条件。实际案例见 [产物污染与删除](references/content-and-observed-edits.md)。

模型输出与 CLI 同样受此要求约束。程序诊断和机器字段放到相应通道，用户屏幕只显示需要的信息。禁止靠更换词语保留同一项自证说明。

## 看真实呈现和行为

有浏览器或截图能力时读取渲染结果，并执行受影响操作；动态文案从实际状态读取。对照用户目标修改布局、状态和内容。扫描器只帮助发现词形，语义判断必须阅读页面上下文。

真实路径、呈现和必要操作成立后交付。禁止把页面审阅转成固定多轮打分、证据截图库或新的 UI 验收制度。

设计批量导入或长时间操作的界面时，读取[状态与恢复的完整交互](references/bulk-import-interaction.md)，让文案、动作和后端状态一起完成用户任务。
