# Release and delivery

Resolve the requested version, target, source changes, publishing mechanism, and project release policy. Separate preparing notes from an authorized publication. Derive release notes from current changes and actual commitments; do not include unrelated activity logs.

Check source state, version inputs, build artifacts, package contents, and consumer installation when those paths changed. Prefer the project toolchain and one coherent release path. Follow the existing published-API and data migration commitments when they apply.

Before an external write, establish the actual publication authorization and credentials. After an interrupted or partial release inspect the remote state: complete missing actions when the prior results match, and get a decision before overwriting a conflicting tag or public asset. Deliver the exact version, URLs, and observed remote status.
