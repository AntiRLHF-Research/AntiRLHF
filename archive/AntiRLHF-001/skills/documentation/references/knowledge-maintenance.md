# Single source of truth and living project knowledge

Give each maintained fact one accountable source: configuration, documented behavior, actual implementation, observational evidence and historical release facts can have different owners. Link or generate dependent text from its owning source when appropriate. When they conflict, resolve the real current requirement and update the incorrect owner and consumers.

An entrypoint explains available actions and navigation; a current guide explains present behavior; research notes preserve evidence and hypotheses; a changelog records actual past releases. A new topic deserves its own file only if it has an independent maintenance lifecycle. Avoid creating a full directory taxonomy or mandatory status ledger for one local correction.

When deleting obsolete terminology or features, update present-tense documentation directly, remove dead anchors and generated derivatives, and keep actual release history in its own record. Never turn a correction into a standing prohibition of the old phrase across unrelated writing. Maintain translations and examples that share the affected fact.

Only promote an incident into a persistent Agent instruction when it changes a repeatable future action; correct an existing responsible instruction before adding a new global rule. Keep temporary session logs in the task's own state, not in the project's permanent authority files.
