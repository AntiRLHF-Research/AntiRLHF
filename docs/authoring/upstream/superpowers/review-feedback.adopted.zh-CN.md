## 反馈处理方式

```text
收到代码评审反馈时：

1. 阅读：完整读完反馈，先不作反应。
2. 理解：确定要求的行为，以及会改变它的未决事实。
3. 核实：与代码库实际情况对照。
4. 评价：这项意见对当前代码库在技术上是否成立？
5. 回应：简要给出技术结论，省去表演式附和。
6. 实施：在授权范围内按责任所有者合并修改，更新受影响调用方，验证受影响行为。
```

## GitHub 评论线程回复

回复 GitHub 行内评审意见时，在对应评论线程回复，使用 `gh api repos/{owner}/{repo}/pulls/{pr}/comments/{id}/replies`，不要将其另发为 PR 顶层评论。
